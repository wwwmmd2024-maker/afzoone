# راهنمای نصب و آماده‌سازی فروش

## ۱. تفاوت دو بخش پروژه

- **افزونه مشتری:** پوشه `product-image-finder`؛ داخل وردپرس مشتری نصب می‌شود.
- **سرور فروشنده:** فقط فایل `license-server/server.php`؛ روی هاست خودتان اجرا می‌شود، مستقل از وردپرس.

پیش از تحویل به خریدار باید یک بار سرور را راه بیندازید و ZIP اختصاصی بسازید. مشتری فقط ZIP و کد لایسنس را می‌گیرد، نه فایل سرور و رمزهای شما.

## ۲. آماده کردن هاست لایسنس

۱. یک زیردامنه با گواهی معتبر HTTPS مانند `licenses.example.com` بسازید.
۲. PHP ۸.۰ یا بالاتر با OpenSSL فعال لازم است؛ برای تولید، نسخه پشتیبانی‌شده PHP ۸.۳+ توصیه می‌شود. فایل‌سیستم محلی با پشتیبانی `flock` و `rename` اتمیک لازم است. این نسخه برای چند سرور همزمان یا NFS طراحی نشده است.
۳. فایل `server.php` را داخل ریشه عمومی همین زیردامنه بارگذاری کنید.
۴. یک پوشه **خارج از تمام ریشه‌های عمومی وب** بسازید؛ مثلاً `/home/account/pif-private`. نام کاربری و مسیر حساب شما متفاوت خواهد بود. این مسیر نباید از هیچ دامنه یا alias هاست قابل دانلود باشد. تکیه بر مخفی کردن نام فایل یا `.htaccess` کافی نیست.
۵. دو رمز متفاوت و تصادفی بسازید؛ هر کدام حداقل ۳۲ کاراکتر. نمونه ساخت محلی:

```bash
python3 -c 'import secrets; print(secrets.token_hex(32))'
```

این فرمان را برای هر رمز جدا اجرا کنید. رمزها را در چت، گیت، ZIP افزونه یا تصاویر آموزشی قرار ندهید.

۶. از پنل هاست متغیرهای محیطی زیر را تنظیم کنید:

| متغیر | مقدار |
|---|---|
| `PIF_ADMIN_TOKEN` | رمز خصوصی مدیریت |
| `PIF_WEBHOOK_SECRET` | رمز جداگانه برای آداپتور خرید؛ اختیاری تا زمان اتصال |
| `PIF_STORAGE_DIR` | مسیر مطلق پوشه خصوصی |

اگر هاست امکان متغیر محیطی ندارد، مقدارهای خالی ابتدای **نسخه روی هاست** `server.php` را ویرایش کنید:

```php
'admin_token' => getenv('PIF_ADMIN_TOKEN') ?: 'YOUR_RANDOM_ADMIN_SECRET',
'webhook_secret' => getenv('PIF_WEBHOOK_SECRET') ?: 'YOUR_DIFFERENT_RANDOM_WEBHOOK_SECRET',
'storage' => getenv('PIF_STORAGE_DIR') ?: '/home/account/pif-private',
```

مقادیر نمونه بالا رمز قابل استفاده نیستند؛ با رمزهای تولیدشده خودتان عوض کنید. نسخه ویرایش‌شده را به مخزن برنگردانید. هنگام ارتقا ابتدا تنظیمات و اطلاعات خصوصی را پشتیبان بگیرید.

۷. نشانی HTTPS فایل را باز کنید. رمز مدیریت را در پنل وارد کنید و «راه‌اندازی / دریافت کلید عمومی» را بزنید.
۸. `public_key` را از پاسخ کپی کنید و در یک فایل متنی `public.pem` ذخیره کنید. اگر از JSON خام کپی می‌کنید، `\n` باید به شکست خط واقعی تبدیل شود؛ خود گیومه‌های JSON جزو PEM نیستند.

فایل‌های زیر خودکار در پوشه خصوصی ایجاد می‌شوند:

- `signing-private.pem`: کلید **خصوصی** RSA؛ فقط روی سرور بماند.
- `licenses.txt`: هر خط یک رکورد JSON؛ شامل کد واقعی لایسنس، سفارش، وضعیت و دامنه.
- `database.lock`: هماهنگی نوشتن فایل.
- `rate-limits.json`: محدودیت درخواست‌ها؛ هش IP با عمر کوتاه.

ممکن است `licenses.txt` تنها پس از اولین صدور ایجاد شود. فایل‌ها با دسترسی ۰۶۰۰ و پوشه جدید با ۰۷۰۰ ایجاد می‌شوند. مسئولیت دسترسی پوشه موجود و بکاپ‌ها با مدیر هاست است.

### نکات HTTPS و وب‌سرور

- سرویس درخواست HTTP را با کد ۴۲۶ رد می‌کند؛ فقط HTTPS استفاده کنید.
- پشت reverse proxy، وب‌سرور مورد اعتماد باید وضعیت TLS را با `HTTPS=on` به PHP بدهد. هدر دلخواه مشتری نباید معیار اعتماد باشد.
- وب‌سرور باید `Authorization` را به PHP عبور دهد. در بعضی Apache/FastCGIها، فعال کردن `CGIPassAuth On` یا تنظیم معادل هاست لازم است. در Nginx می‌توان `fastcgi_param HTTP_AUTHORIZATION $http_authorization;` را در پیکربندی مناسب گذاشت.
- اندازه بدنه درخواست را در وب‌سرور هم محدود کنید؛ مثال Nginx: `client_max_body_size 32k;`.
- برای پنل و APIهای مدیریتی، محدودیت IP/VPN یا قوانین فایروال هاست مفید است. پنل روی خود صفحه رمز را نگه می‌دارد و آن را در localStorage ذخیره نمی‌کند؛ روی کامپیوتر مشترک پس از کار تب را ببندید.
- اگر init خطای `server_error` داد، OpenSSL، فایل پیکربندی OpenSSL هاست، دسترسی نوشتن پوشه و لاگ PHP را بررسی کنید.

## ۳. ساخت ZIP فروشنده

Python ۳ روی کامپیوتر خود داشته باشید. در ریشه پروژه:

```bash
python3 tools/build.py \
  --server-url https://licenses.example.com/server.php \
  --public-key public.pem \
  --output vendor-build/product-image-finder-1.0.0.zip
```

بسته‌ساز فقط افزونه را بسته‌بندی می‌کند؛ سرور، رمزها و تست‌ها وارد ZIP مشتری نمی‌شوند. نسخه ساخته‌شده شامل آدرس HTTPS و کلید عمومی است؛ عمومی بودن این دو اطلاعات عیب امنیتی نیست.

اگر Python ندارید، مقادیر `server_url` و `public_key` در `product-image-finder/vendor-config.php` را دستی تنظیم کنید و **همان پوشه `product-image-finder`** را ZIP کنید. PEM باید با BEGIN/END و شکست خط صحیح داخل رشته PHP باشد. پوشه افزونه باید در ریشه ZIP باشد، نه کل مخزن.

**هرگز `signing-private.pem`، admin token، webhook secret یا `licenses.txt` را در فایل‌های افزونه قرار ندهید.**

## ۴. صدور دستی و تحویل به مشتری

۱. پنل سرور را باز کنید و رمز مدیریت را وارد کنید.
۲. شناسه واقعی و یکتای سفارش و بازار مربوطه را انتخاب کنید؛ تاریخ انقضا اختیاری است. خالی یعنی مادام‌العمر در سطح رکورد لایسنس، نه توکن کش‌شده.
۳. «صدور» را بزنید. همان شناسه سفارش در همان بازار دوباره همان کد را می‌دهد و کد تازه ایجاد نمی‌کند.
۴. کد و ZIP پیکربندی‌شده را از طریق روش مجاز آن بازار برای خریدار بفرستید.
۵. خریدار افزونه را نصب می‌کند، وارد صفحه «تصویرجو» می‌شود و کد را تأیید می‌کند. اولین فعال‌سازی، لایسنس را به دامنه متصل می‌کند.

لایسنس نقش رمز مالکیت دارد؛ آن را عمومی نکنید. `www.example.com` و `example.com` یک دامنه محسوب می‌شوند. زیردامنه‌های دیگر جدا هستند. این نسخه دامنه را می‌بندد، نه یک نصب خاص: چند نصب در مسیرهای متفاوت همان دامنه سهمیه جدا محسوب نمی‌شوند. localhost پشتیبانی نمی‌شود؛ برای staging یک دامنه و لایسنس آزمایشی جدا بدهید.

## ۵. استفاده در وردپرس

۱. وردپرس تک‌سایته و ووکامرس را فعال کنید. ویرایشگر **کلاسیک محصولات** را به کار ببرید.
۲. ZIP را از «افزونه‌ها ← افزودن ← بارگذاری» نصب و فعال کنید.
۳. کد لایسنس را وارد کنید. سرور شما باید از هاست مشتری روی HTTPS قابل دسترسی باشد.
۴. منبع پیش‌فرض Commons است. برای Brave، مشتری باید کلید Search API دارای دسترسی Image Search و سهمیه کافی داشته باشد و آن را در تنظیمات وارد کند.
۵. محصول را ویرایش کنید و در کادر تصویرجو نام یا مدل را جست‌وجو کنید؛ نام انگلیسی معمولاً نتیجه دقیق‌تری دارد.
۶. منبع و حقوق استفاده را بررسی کنید. پس از تأیید، «تصویر شاخص» یا «افزودن به گالری» را بزنید.

ثبت تصویر بلافاصله انجام می‌شود؛ سایر تغییرات محصول نیاز به ذخیره معمول ووکامرس دارند. تصویر شاخص قبلی از رسانه حذف نمی‌شود. عکس‌ها hotlink نمی‌شوند؛ فایل در کتابخانه سایت ذخیره می‌شود. SVG، GIF و فایل غیرتصویری پذیرفته نمی‌شود.

## ۶. انتقال، لغو و خرابی سرور

- **انتقال دامنه:** با بررسی مالکیت خریدار، در پنل «آزادسازی دامنه» بزنید؛ سپس مشتری روی دامنه جدید فعال کند. دامنه قبلی ممکن است تا پایان توکن ۲۴ساعته هنوز کار کند.
- **استرداد وجه:** لایسنس را در پنل لغو کنید. اتصال خودکار به استرداد بازار در این نسخه وجود ندارد.
- **قطع سرور:** تا پایان توکن معتبر، عملیات ادامه می‌یابد؛ بعد از انقضا متوقف می‌شود. WP-Cron تقریباً هر ۶ ساعت به‌روز می‌کند؛ زمان واقعی به ترافیک/کرون هاست وابسته است. دکمه «بررسی مجدد» دستی هم وجود دارد.
- **تعویض کلید خصوصی:** همه ZIPهای قبلی کلید عمومی قبلی را دارند. از کلید اصلی نسخه پشتیبان امن داشته باشید؛ تولید بی‌برنامه کلید جدید، مشتریان قبلی را از اعتبارسنجی می‌اندازد. چرخش کلید چندمرحله‌ای در این نسخه پیاده نشده است.
- **بکاپ:** از کل پوشه خصوصی نسخه رمزگذاری‌شده خارج از وب بگیرید. برای بکاپ سازگار، سرویس را موقتاً نگه دارید یا ابزار بکاپی استفاده کنید که `database.lock` را رعایت کند. فایل txt را همزمان با سرویس به صورت دستی ویرایش نکنید.

## ۷. قبل از فروش

چک‌لیست [امنیت و آزمون انتشار](security-and-testing-fa.md) را کامل کنید. سیاست حریم خصوصی، اطلاعات پشتیبانی، دوره اعتبار لایسنس و شرایط تجاری خود را اضافه کنید. سازگاری سیستم لایسنس مستقل و مجوز کد با مقررات بازار را از خود بازار تأیید بگیرید؛ این مخزن به معنی تأیید فروشگاه نیست.
