# امنیت و آزمون پیش از انتشار

## مدل امنیت

کسی که کنترل هاست و کد PHP را دارد می‌تواند شرط‌های افزونه را تغییر دهد. نه کدگذاری Base64 و نه مخفی کردن نام فایل، افزونه را ضدکرک نمی‌کند. این پروژه عمداً از ادعای «غیرقابل کرک» یا مبهم‌سازی نمایشی استفاده نمی‌کند.

کنترل‌های موجود:

- تولید لایسنس با `random_bytes` و ۱۲۸ بیت تصادف.
- بستن دامنه و بررسی وضعیت و انقضا سمت سرور.
- امضای RSA/SHA-256 با کلید خصوصی خارج از وب و کلید عمومی ثابت در ZIP.
- جلوگیری از پذیرفتن پاسخ جعلی شبکه یا تغییر ساده توکن؛ بررسی دامنه، محصول، هش کد و زمان.
- رمز مدیریت مستقل، وب‌هوک HMAC زمان‌دار و صدور idempotent.
- فایل txt خصوصی، `flock` و نوشتن اتمیک؛ توکن و لایسنس در URL درخواست قرار نمی‌گیرند.
- nonce وردپرس، کنترل مجوز ویرایش همان محصول و آپلود، و اعتبارسنجی لایسنس در هر عملیات AJAX؛ مخفی کردن دکمه تنها کنترل نیست.
- واردکردن تصویر فقط از نتیجه جست‌وجوی ذخیره‌شده همان کاربر و محصول؛ کاربر URL دلخواه ارسال نمی‌کند.
- HTTPS، WP safe HTTP برای بررسی نشانی مقصد و هر redirect، سقف حجم و ابعاد، تشخیص MIME واقعی و رد SVG.
- خروجی متنی پاک‌سازی/escape شده؛ داده سرویس جست‌وجو به عنوان HTML خام در مرورگر اجرا نمی‌شود.

## محدودیت‌های آگاهانه

- نسخه دستکاری‌شده افزونه می‌تواند کنترل محلی را حذف کند. برای کنترل تجاری قوی‌تر، ارزش اصلی سرویس باید روی سرور باقی بماند. در این نسخه جست‌وجو روی سرور مشتری انجام می‌شود.
- رمز مدیریت یک عامل احراز هویت است؛ پنل MFA و حساب چندمدیره ندارد. از VPN/محدودیت IP، HTTPS و رمزهای بلند استفاده کنید.
- کد واقعی لایسنس برای امکان بازیابی و لیست txt ذخیره می‌شود. خواندن فایل خصوصی توسط مهاجم به معنی افشای کدهاست. سرقت کلید خصوصی نیز نیازمند تعویض کلید و انتشار بسته جدید است.
- متادیتای منبع در رسانه ثبت می‌شود ولی نمایش attribution در قالب فروشگاه تضمین نمی‌شود. هر مجوز را جدا بررسی کنید؛ بعضی نتایج یا نشانه‌های تجاری محدودیت اضافی دارند.
- وقفه سرور تا پایان توکن تحمل می‌شود. توکن قبلی بعد از reset/revoke حداکثر ۲۴ ساعت می‌تواند روی نصب آفلاین معتبر بماند.
- دامنه، هویت سخت‌افزاری یا نصب خاص نیست؛ چند نصب در یک hostname از هم جدا نمی‌شوند. multisite و ویرایشگر جدید محصول خارج از محدوده این نسخه‌اند.
- ظرفیت txt محدود است. این نسخه ذخیره‌ساز توزیع‌شده، سامانه آدیت کامل، پایش، ایمیل تحویل کد یا اتصال رسمی بازار ندارد.
- استانداردهای حقوقی/مجوزی فروشگاه، سیاست حریم خصوصی و مجوز GPL کد را پیش از فروش بررسی کنید. فروش خدمات و پشتیبانی ممکن است، اما حقوق دریافت‌کننده تحت مجوز کد باید رعایت شود.

## آزمون خودکار انجام‌شدنی

```bash
npm install --prefix .tools @php-wasm/cli@3.1.58
node tests/integration.mjs
PHP_VERSION=8.0 node tests/integration.mjs
node --check product-image-finder/assets/admin.js
find product-image-finder license-server -name '*.php' -exec php -l {} \;
python3 tools/build.py
```

اگر PHP محلی ندارید، به جای `php` از `node .tools/node_modules/@php-wasm/cli/php-wasm.js` استفاده کنید. برای اجرای CI نسخه جدید Node مطابق پیش‌نیاز بسته PHP.wasm به کار می‌رود.

آزمون یکپارچه ۴۰ مورد را بررسی می‌کند: احراز هویت، JSON و سقف بدنه، عدم تغییر با GET، خصوصی بودن پوشه، تولید کلید و کد، تکرار سفارش، اتصال دامنه، زمان اعتبار، امضای OpenSSL و تأیید مستقل در Node، رد توکن دستکاری‌شده/منقضی، بررسی واقعی کلاس لایسنس افزونه با حداقل توابع شبیه‌سازی‌شده وردپرس، انتقال دامنه، لغو، وب‌هوک، پرداخت ناقص و محدودیت درخواست.

**مرز نتایج:** این تست‌ها PHP واقعی را در WebAssembly اجرا می‌کنند، اما وردپرس و ووکامرس کامل اجرا نمی‌شوند و APIهای Wikimedia/Brave زنده آزمایش نمی‌شوند. موفقیت این تست‌ها اثبات آمادگی انتشار روی همه هاست‌ها نیست.

## چک‌لیست لازم روی هاست واقعی

- [ ] سرور با HTTPS و OpenSSL درست راه‌اندازی شود؛ HTTP رد شود.
- [ ] `licenses.txt` و کلید خصوصی از هیچ دامنه/alias قابل دانلود نباشند.
- [ ] پنل بدون رمز نتواند کلید صادر کند؛ Authorization از وب‌سرور عبور کند.
- [ ] دو درخواست همزمان برای یک سفارش فقط یک کد بدهند؛ بکاپ و بازیابی تست شود.
- [ ] ZIP فروشنده در یک وردپرس تمیز نصب شود و صفحه لایسنس نمایش داده شود.
- [ ] افزونه بدون ووکامرس پیام مناسب دهد و سایت را مختل نکند.
- [ ] بدون لایسنس یا با کد جعلی، AJAX جست‌وجو و ثبت تصویر هم ۴۰۳ بدهند.
- [ ] لایسنس معتبر فعال شود؛ کپی آن به دامنه دیگر رد شود؛ تغییر www مجاز باشد.
- [ ] برای ساعت اشتباه هاست، قطع سرور، انقضا و لغو، رفتار مطابق توکن محدود مشاهده شود.
- [ ] Commons با نام فارسی و انگلیسی آزمایش شود؛ نتیجه خالی و خطای شبکه پیام قابل فهم بدهند.
- [ ] Brave با حساب واقعی دارای سهمیه آزمایش شود؛ خطای API پیام مناسب بدهد.
- [ ] تصویر JPG/PNG/WebP واقعی در رسانه ثبت شود؛ فایل بزرگ، SVG و پاسخ HTML رد شوند.
- [ ] ثبت تصویر شاخص، جایگزینی، گالری، تغییرات ذخیره‌نشده و زدن «به‌روزرسانی محصول» تصویرها را ناخواسته حذف نکنند.
- [ ] مدیر فروشگاه مجاز بتواند تصویر وارد کند؛ کاربر بدون مجوز نتواند محصول دیگری را تغییر دهد.
- [ ] دوبار کلیک، نتایج منقضی‌شده، صفحه موبایل و وضعیت‌های خطا بررسی شوند.
- [ ] منبع، نام هنرمند و مجوز در رسانه بمانند؛ اعتبار لازم در صفحه عمومی محصول واقعاً نمایش داده شود.
- [ ] غیرفعال‌سازی/حذف افزونه تصاویر محصول را حذف نکند؛ کرون و تنظیمات پاک شوند.
- [ ] تحویل خودکار فقط با قرارداد واقعی بازار و پس از تأیید خرید واقعی آزمایش شود؛ وب‌هوک ساختگی به معنی اتصال بازار نیست.

## گزارش اشکال

هنگام گزارش، نسخه WordPress/WooCommerce/PHP، کد خطا و مسیر اقدام را بنویسید. رمز مدیریت، لایسنس مشتری، کلید API، PEM خصوصی و `licenses.txt` را ضمیمه نکنید.
